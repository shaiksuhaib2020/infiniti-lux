## PART 0 — APPROACH FOR THIS TURN

This turn covers **7 pages**: Flights, Holidays, Tours & Experiences, Hotels, Honeymoons, Cruises, and Corporate Travel. Rather than building 7 separate pages from scratch, the agent builds **one shared template component** and populates it with per-page configuration data. This is the correct Next.js pattern — efficient, consistent, and easy to update.

**Two deliverables this turn:**

1. `components/service/ServicePageTemplate.jsx` — the shared layout component
2. Seven page files, each importing the template with its own config

Phase 1 rule remains firm: **no booking engines, no APIs.** Every page exists to build trust in the service and convert the visitor to a WhatsApp enquiry or Contact form submission. These should feel like genuine, complete service pages — not "coming soon" placeholders.

## PART 1 — SHARED TEMPLATE STRUCTURE

Every service page renders exactly **4 sections** in this order. No exceptions in Phase 1.

```
1. Service Hero
2. What We Offer
3. Popular Options
4. Enquiry CTA
```

The shared Navbar and Footer are inherited from `layout.jsx` — the agent does not re-add them here.

### Section 1 — Service Hero

**Height:** `72vh` — impactful, but deliberately not full viewport. Leaving content visible below the fold signals to the visitor that there is more to read, which increases scroll rate. Full-viewport hero is reserved for the homepage only.

**Background:**
The service's own image fills the section with `object-fit: cover`. Over it, a gradient overlay: `linear-gradient(to right, rgba(7,17,28,0.80) 0%, rgba(7,17,28,0.40) 100%)`. The heavy side is left, so text sits on a dark base. The right side breathes, letting the photography show. This is a cinematic technique, not a flat dimming.

**Content — positioned left-aligned, vertically centered, within `--page-max-width`:**

Top to bottom:

1. **Service label** — `--font-body`, 12px, `--color-gold`, weight 500, letter-spacing 0.06em. Text is the service category name in sentence case (e.g., "Flight services" not "FLIGHTS"). Sits 8px above the headline. This is subtle identification, not a decorative eyebrow — it has genuine navigational purpose.

2. **Headline** — `--font-display`, `--text-hero` (72px on desktop, 48px on tablet, 38px on mobile), white, weight 300, line-height 1.08. Each page has its own unique headline — specified in Part 2.

3. **Supporting line** — `--font-body`, 17px, white at 75% opacity, weight 400, line-height 1.5. Max-width 520px so it doesn't stretch wide. One sentence only.

4. **CTA row** — two buttons, 16px gap, 40px below the supporting line:
   - **Primary:** "Enquire on WhatsApp" — background `--color-whatsapp`, white text, weight 600, 15px, radius `--radius-button`, padding `14px 26px`. Opens pre-filled WhatsApp for this service.
   - **Secondary:** "Contact Us" — transparent background, `1px solid rgba(255,255,255,0.50)`, white text, same sizing. Routes to `/contact` with service type pre-selected via query param (e.g., `/contact?service=flights`).

**GSAP entrance animation:** Headline fades in and rises 24px over 0.7s on page load. Supporting line follows with 0.15s delay. CTAs follow with 0.25s delay. Use `power2.out` easing.

## PART 2 — PER-PAGE SPECIFICATIONS

### How to implement this in Next.js

The agent creates a `serviceConfigs` object — either in a separate `lib/serviceConfigs.js` file or inline in each page. Each page imports `ServicePageTemplate` and passes its config as props.

Each config object contains:
- `serviceName` — short label (used in service hero label and document title)
- `heroImage` — local path to image in `/public/assets/cards/`
- `heroHeadline` — Cormorant Garamond display headline
- `heroSupporting` — one supporting sentence
- `whatsAppMessage` — URL-encoded pre-filled message
- `offerHeading` — heading for the What We Offer section
- `offerParagraphs` — two short paragraphs (array of 2 strings)
- `benefits` — array of 4 objects with `title` and `description`
- `highlights` — array of 3 objects with `value` and `label` (for the dark right-column card)
- `popularHeading` — heading for Popular Options section
- `popularSubtext` — one-line subtext
- `popularOptions` — array of 4 objects with `name`, `description`, `imageQuery`
- `enquiryCTAHeading` — heading for the dark Enquiry CTA section
- `enquiryCTASupporting` — one supporting sentence

## PART 3 — DESIGN DETAILS SPECIFIC TO THIS TURN

### Applying the Updated Palette

All seven pages use the updated color system from the design overhaul (Turn 2 design brief). Specific checks for the agent:

- Hero overlays use the gradient defined above — `rgba(7,17,28,0.80)` to `rgba(7,17,28,0.40)` — not a flat dark overlay
- The `--color-gold` accent appears only on: service label, benefit bar, dark card value numbers, active nav item
- Section 2 (`What We Offer`) background is `--color-white`
- Section 3 (`Popular Options`) background is `--color-ice`
- Section 4 (`Enquiry CTA`) background is `--color-abyss`
- This light/light/dark alternation creates clear visual rhythm across every page

### Typography Reminders

- Hero headlines: Cormorant Garamond, weight 300 — not 400. Weight 300 at 72px is more premium than 400.
- Paragraph text: Inter 16px — never Cormorant at body size. Cormorant below 22px is hard to read on screen.
- The dark card highlights (Section 2 right column): Cormorant 40px for the value, Inter 13px for the label. This pairing — large serif value, small sans-serif label — is a refined typographic moment.

### Scrolling Into Sections

Apply ScrollTrigger reveals across all sections. **The agent must not apply identical fade-and-rise animations to every element on every page** — that reads as generated. Instead:

- Section 1 hero: entrance animation only (page load)
- Section 2: left column reveals first, right column (dark card) reveals 0.2s after — a subtle left-to-right read
- Section 3 cards: stagger reveal, 0.1s per card, left to right
- Section 4: full section content fades in together as a single unit — no stagger

### Active Nav State

Whichever travel page is active, the Navbar should reflect it. The "Travel" pill item in PillNav should be in the `.is-active` state when on any `/travel/*` route, and the Corporate Travel link highlights when on `/corporate-travel`. The agent handles this by reading `usePathname()` from Next.js and passing it to `activeHref`.

## PART 4 — ROUTING AND PHASE 1 RULES

**All 7 pages:** Every link that would go to a booking engine goes instead to WhatsApp (pre-filled) or `/contact` with a service query param. The agent ensures:

- No external booking URLs are linked
- No forms collect payment information
- No availability checking occurs
- The `/contact` page receives the query param `?service=[serviceName]` and uses it to pre-select the relevant service checkbox
